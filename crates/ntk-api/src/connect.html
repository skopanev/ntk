Подключение к NTK

Локальный stdio-клиент удалён 21.09.2026. Клиенты ходят на HTTP MCP сами.

Он никогда не был второй реализацией: открывал MCP на stdio и пересылал вызовы на этот же сервис. Посредник означал вторую поверхность, которую надо держать в паритете, вторую сборку, вторую вещь, установленную на машинах, и второй способ отстать от сервера.

Установленный бинарник продолжит работать до переустановки. Это не значит, что он в порядке: он ходит на тот же сервер, но его набор инструментов заморожен на дне удаления и с сервером расходится.

1. Заменить подключение

Имя сервера оставьте прежним — ntk. Меняется только то, как клиент до него добирается. Признак старой записи: в ней есть "command": "ntk" (или абсолютный путь к бинарнику) и "args": ["mcp"].

Claude Code

claude mcp remove --scope user ntk
claude mcp add --transport http --scope user ntk __URL__/mcp-claude

Если старая запись была в project- или local-scope, заменяйте в том же scope: старая проектная запись перекрывает новую глобальную, и вы получите старое поведение, ничего не заметив.

Claude или agy, конфигурация JSON

Замените только объект ntk внутри mcpServers:

"ntk": {
  "type": "http",
  "url": "__URL__/mcp-claude"
}

Codex

Замените блок [mcp_servers.ntk] в активном config.toml:

[mcp_servers.ntk]
url = "__URL__/mcp-claude"

Уберите из старой записи command, args и переменные окружения, нужные только клиенту. Остальные MCP-серверы и прочие настройки не трогайте.

2. Перезапустить сессию клиента

Конфигурация читается на старте. Если клиент живёт в контейнере — нужна новая сессия контейнера.

3. Войти заново

Сохранённый ключ старого клиента не превращается в OAuth-сессию HTTP-клиента. Это разные вещи.
  1. Claude Code или agy: /mcp → ntk → Authenticate.
  2. Codex CLI: codex mcp login ntk из терминала с той же конфигурацией Codex. После успеха перезапустите сессию Codex.
  3. Codex app: настройки MCP-сервера → Authenticate.

Входите рабочим Google-аккаунтом. Одна личность на человека: область доступа живёт на сервере, поэтому один вход покрывает все ваши воркспейсы.

Ключи API руками никто не выдаёт, и OAuth через curl городить не надо. Если клиент просит ключ — вы не там.

4. Дожать вход в браузере

На странице NTK нажмите Copy sign-in link и вставьте ссылку целиком в ожидающий запрос клиента — вместе с code и state, не только код и не ссылку от прошлой попытки. Истёкшая попытка не чинится, она начинается заново.

Клиентам без окна вставки нужен Return to app и доступный из браузера локальный callback. Codex ждёт именно локальный callback — в контейнере его надо пробросить наружу.

5. Проверить и снести бинарник

Убедитесь, что ntk подключён и показывает инструменты, и только потом удаляйте локальный исполняемый файл тем же способом, которым он ставился. Тикеты и доступы остаются на том же сервере — удаляется только посредник.

.ntkrc больше не читается ничем. Он привязывал каталог к воркспейсу для терминального клиента; клиента нет, воркспейс теперь едет в самом вызове. Файлы, оставшиеся в репозиториях, инертны.

Что изменилось в инструментах

Это увидят все, включая тех, кто уже на HTTP.

  • ntk_ls больше не отдаёт тела тикетов. Замер: тело тянет около 2600 знаков, страница по умолчанию в пятьдесят тикетов давала около ста тридцати тысяч, а при разрешённом потолке в пятьсот — за миллион, то есть за пределы любого контекста. Теперь в ответе идентификатор, заголовок, статус, теги, даты. Нужны тела — body=true. Одно тело — через ntk_show.
  • Ответ больше не молчит об усечении. Появились truncated и next_offset. Раньше пятьдесят строк из пяти тысяч выглядели ровно так же, как пятьдесят из пятидесяти, и полная страница читалась как весь ответ.
  • У ntk_attach убрано поле path. Оно обещало «локальный stdio MCP», которого больше нет. Отправляйте content для текста или content_base64 для двоичных файлов: сервер на другой машине и путь на вашем диске прочитать не может.
  • ntk_restore вернёт удалённый тикет. Если что-то снесли, оно не потеряно.
  • Старая MCP-сессия прекращается. Состав инструментов изменился, поэтому сервер ответит 404 session terminated: the tool set has changed. Это не поломка: клиент обязан переподключиться и перечитать список. Нормальные клиенты делают это молча.

Кого пускают

Вход только по рабочему Google-аккаунту разрешённых доменов. Личная почта отклоняется с объяснением; отдельный адрес может добавить администратор поимённо.
